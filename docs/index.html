About

Data

Download counts come from ClickPy, ClickHouse's public copy of the PyPI download logs, which goes back to 2016. "All" leaves out installers that mirror PyPI wholesale (bandersnatch, devpi, Nexus, Artifactory, z3c.pypimirror). The period of 30 to 180 days shows the 7-day rolling mean of daily downloads; "All years" shows the mean per day of each month. The data are refreshed weekly.

Packages

"Listed" packages are a hand-picked list, every PyPI package of best-of-atomistic-machine-learning, and the simulation engines of atomistic.software that install from PyPI. "With dependents" adds the most-downloaded packages whose latest release requires a listed package, directly or through other dependents; a dependency declared only in an optional extra does not count, and general-purpose libraries such as RDKit and DGL are not followed. A dependent takes the category of the package it was found through. Suggest a package.

Downloads are not users

CI services, container builds and cluster jobs install packages over and over, so download counts measure installs, not people. Two columns of the table estimate this over the last days. CI is the share whose installer reported a CI run; pip and uv report one when a variable such as CI is set, as on GitHub Actions and GitLab CI. Bulk rebuilds is the share that came, without a CI flag, from one pinned environment downloading the same version at least times on one day (same installer, Python, OS, glibc and country): a Docker image or batch job rebuilt many times rather than many users.

Automated installs run almost entirely on Linux, so "macOS + Windows" leaves them out; it also leaves out real use on Linux workstations and clusters, and is therefore a floor on interactive use, not an estimate of it. Installs from outside PyPI, such as conda-forge, are not counted.
